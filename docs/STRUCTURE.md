# design.wolf.ua — структура (набросок для обсуждения)

2026-11-08. Основа — `design-wolf-ua-concept.md` v2.1. Это предложение, не утверждено.
Таблицы: префикс `design_`, InnoDB, `utf8mb4_unicode_ci`, комментарии на украинском (как у calendar v2). Деньги — целые гривны (`int`), потому что `transaction.payment_done` — `decimal(7,0)`.

### Что пишем в общие таблицы

| Таблица | Что | Как |
|---|---|---|
| `customers.inv_sum` + `transaction` | Списание у клиента, начисление дизайнеру, пополнение от WFP | Одна функция, одна транзакция БД. `paymethod` = `[design] Оплата замовлення №N` / `[design] Гонорар …` / `[design] Поповнення WayForPay …` |
| `customers_cloud` + симлинк в `/mnt/cloud/f/…` | Купленные макеты | `type_id=1`, `original_name` = «Дизайн №N — Візитка 1.pdf» |

Только чтение: `customers`, `orders`, `orders_files`, `users`.

## 2. Статусы

**Заказ (`design_orders.status`):**

| # | Статус | Кто ведёт дальше |
|---|---|---|
| 1 | Чернетка | Клиент: заполнить и опубликовать |
| 2 | Збір пропозицій (режим 1) | Дизайнеры предлагают, клиент выбирает |
| 3 | Очікує відповіді дизайнера (режим 2) | Дизайнер: да / нет |
| 4 | В роботі | Дизайнер: превью, макеты. Клиент: «Купую» |
| 5 | Очікує оплати рахунку | Бухгалтерия, потом автоматически |
| 6 | Куплено | Готово. Дизайнер может «ще не закінчили» → 7 |
| 7 | Доопрацювання | Как «В роботі», потом снова «Купую» → 5 или 6 |
| 8 | Скасовано | — |

Жалоба — не статус, а запись в `design_complaints`: заказ остаётся «Куплено».

**Предложение (`design_offers.status`):** 1 запрошено (режим 2), 2 відмовився, 3 надіслано, 4 обрано, 5 обрано іншого, 6 відкликано дизайнером.

## 3. Экраны

**Публичные:**
- Главная «Майстерня дизайну»: как это работает, работы из портфолио.

**Для вошедших:**
- Список дизайнеров и профиль дизайнера с портфолио.

**Клиент:**
1. Новый бриф: продукт → вопросы → режим → (режим 2) выбор дизайнера → «Опублікувати».
2. Мои заказы.
3. Заказ до выбора: бриф + список предложений (Петя, Вася, Шура: цена, срок, текст). Клик открывает переписку с этим дизайнером и кнопку «Обрати».
4. Рабочее пространство: шапка (дизайнер, цена, срок, статус), лента с превью и ответами, список макетов, «Купую», «Скарга» после покупки.
5. Оплата: баланс (если хватает) / WayForPay / счёт.

**Дизайнер:**
1. Заявка: о себе, работы для портфолио.
2. Профиль и портфолио.
3. Лента брифов (статус 2) с кнопкой «Запропонувати себе» (текст, сумма «на руки» с подсказкой «клієнт побачить …», дата).
4. Приглашения (режим 2): «Береш?» — да (та же форма) / нет.
5. Мои предложения и заказы.
6. Рабочее пространство: то же, плюс загрузка превью, загрузка макетов, «Ще не закінчили» (новая цена и дата).
7. Заработок: история начислений из `transaction`.

**Админка (позже, в adminka):** продукты и брифы, заявки дизайнеров, все заказы и переписки, жалобы, настройки.

**Кроны:**
- Бриф без предложений 24 ч → куратору.
- Срок прошёл, покупки нет → куратору.
- Заказы «Очікує оплати рахунку»: деньги на балансе появились → провести покупку.

## 4. Решено 2026-11-09

1. Бриф и заказ — одна таблица `design_orders` и один номер.
2. Поля `transaction.type_id`, `order_id`, `user_id` для строк design — владелец скажет позже.
3. «Дизайнер молчит» и «тишина в работе» — в первый запуск не делаем.
4. Список дизайнеров и профили — только для вошедших (публичная только главная).
5. Дизайнер может отозвать предложение до выбора (статус 6 «відкликано»).
